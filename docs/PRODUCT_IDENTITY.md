# Polymorph Product Identity

Polymorph should feel like a serious cyber-operations platform with training and readiness capabilities, not a training course wearing a SOC skin.

## Identity statement

**Polymorph is the deterministic cyber-operations digital twin.**

It gives defenders a living synthetic enterprise to investigate, operate, break, defend, replay, and learn from.

## Visual and interaction identity

- dense information when density serves investigation;
- restrained professional visual language;
- tool-specific interaction patterns;
- technical data shown directly instead of constantly summarized into beginner prose;
- contextual help available on demand rather than permanently occupying the primary workflow;
- no cartoonish gamification, childish rewards, or course-completion language in professional mode;
- visual hierarchy inspired by real security/operations software without cloning vendor interfaces.

## Distinct application personalities

### SIEM

Search-heavy, data-dense, keyboard-friendly, time-oriented. Tables, raw events, field statistics, filters, query history, correlations.

### EDR

Asset and process centric. Process trees, endpoint timeline, file/network relationships, host actions, acquisition/isolation state.

### Identity

Relationship and access centric. Users, accounts, roles, sessions, applications, authentication history, privilege/risk context.

### Network

Topology and flow centric. Hosts, subnets, protocols, connections, DNS, packet/artifact pivots.

### Email

Message centric. Mailboxes, headers, sender reputation, URLs, attachments, delivery/read/click activity.

### Cloud

Resource and control-plane centric. Accounts/projects/subscriptions, IAM, audit events, resources, configuration drift, exposure paths.

### Case

Operational coordination centric. Evidence graph, hypotheses, tasks, owners, incident phases, actions, decisions, communications, reports.

### Range

Direct system interaction. Terminal, desktop/console where justified, files, processes, services, configuration, network state, acquisition, response.

## UX rule

A user switching between two Polymorph applications should immediately understand that the data belongs to the same incident but the job they are doing has changed.

## Depth rule

Do not summarize away the evidence needed to reason. Provide progressively deeper layers:

1. overview;
2. structured details;
3. raw telemetry/artifact;
4. cross-tool/entity pivots;
5. interactive system state where available.

## Assistance rule

Professional mode assumes competence and keeps assistance quiet. Guided mode may add:

- hints;
- recommended pivots;
- playbooks;
- field explanations;
- technique/context education;
- instructor prompts.

Both modes operate on the same underlying incident.
